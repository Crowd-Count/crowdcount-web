CrowdCount API

for
api.crowdcount.tech

Integrate CrowdCount data into your own application using these public API endpoints.

How It Works

CrowdCount uses a
location-based
architecture. Each
location
has a unique ID and contains one or more
devices
(Crowd Counters). Counts, entries, and history are all tracked at the location level.


To authenticate, provide credentials from any device that belongs to the location. For endpoints that modify a location, you must provide credentials for
all
member devices.


CrowdCount tracks two types of data:

Population
— how many people are currently present (goes up and down)

Entries
— how many people have entered (cumulative, only goes up)

General

Command Description Parameters
GET /ping Returns "pong", indicating that the server is running.
  • None
GET /totalcount Returns the total count of people ever detected across all devices.
  • None
GET /total_entries Returns the total entries ever recorded across all devices.
  • None
POST /check_password Checks if a device password is correct.
  • device_id (required)
  • password (required)
GET /check_user Checks if a device exists and returns its online/offline status.
  • device_id (required)
GET /connection_status Returns the connection status of a device.
  • device_id (required)
POST /set_password Changes a device's password.
  • device_id (required)
  • current_password (required)
  • new_password (required)
GET /get_all_map_locations Returns all public map locations with current counts, overcrowding limits, devices, and comparison data.
No authentication required.
  • None
GET /get_all_location_names Returns a list of names of all public map locations.
  • None

Location Management

Create, update, and query locations. Each location groups one or more Crowd Counter devices and is identified by a UUID location_id.

Command Description Parameters
GET /get_locations_for_device Returns all locations a device belongs to.
  • device_id (required)
  • password (required)
GET /get_location Returns details for a specific location including current count and devices.
  • location_id (required)
  • device_id (required)
  • password (required)
POST /create_location Creates a new location with one or more devices.
Requires credentials for all devices in the location.
  • name (required)
  • credentials (required)
  • overcrowding_limit (optional)
  • color (optional)
POST /update_location Updates a location's name, overcrowding limit, or color.
  • location_id (required)
  • device_id (required)
  • password (required)
  • name / overcrowding_limit / color
POST /replace_location Replaces a location's entire device set.
All new devices must provide valid credentials.
  • location_id (required)
  • credentials (required)
POST /delete_location Deletes a location.
Requires admin authentication.
  • location_id (required)
  • password (required, admin)

Location Counting

Read and modify a location's live population count and entry count.

Command Description Parameters
POST /location/add_to_count Increments a location's population count.
  • location_id (required)
  • credentials (required)
  • count_to_add (required)
POST /location/sub_from_count Decrements a location's population count.
Count will not go below zero.
  • location_id (required)
  • credentials (required)
  • count_to_sub (required)
POST /set_reset_schedule Sets a daily automatic reset time for a location's count.
  • location_id (required)
  • device_id (required)
  • password (required)
  • reset_hour (required, 0-23)
  • reset_minute (optional)
  • timezone (optional)
GET /get_reset_schedule Returns the reset schedule for a location.
  • location_id (required)
  • device_id (required)
  • password (required)
POST /delete_reset_schedule Removes the reset schedule for a location.
  • location_id (required)
  • device_id (required)
  • password (required)

Each endpoint also has an average variant that returns the historical average for the same period.

Important Notes


The
credentials
parameter is a JSON array of [device_id, password] pairs for all devices in the location:

"credentials": [["T1234", "pass1"], ["T5678", "pass2"]]

For single-device authentication, use
POST with JSON body
:

{"device_id": "T1234", "password": "your_password"}

All parameters listed as
required
in history endpoints above. The date format is
yyyy-mm-dd
. For year-based endpoints use a 4-digit year like
2026
.


Server timezone is
UTC
. Convert to your local timezone in your application.


The API endpoint is api.crowdcount.tech
